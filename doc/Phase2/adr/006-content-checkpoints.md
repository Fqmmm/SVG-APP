# ADR 006：内容检查点与标签 dirty 语义

状态：实现完成，通用准备、根配置接入与代码装配分别提交。

## 背景

modified-star 需要判断当前文档是否与最近一次成功读取或保存的内容不同。原 TreeDecorator 上下文只有 document 和 shape，缺少保存点通知及可供不同图形共用的内容快照。

还需要明确新建文档是否标星、子节点变化是否影响祖先，以及 undo 回到保存点后怎样显示。

## 决策

- modified-star 按内容差异标星。undo 回到保存内容后星号消失，redo 后再次出现；move 0 0 等未改变内容的命令不产生差异。
- 新建文档尚无保存基线，画布和新节点立即标星，包括空画布，无需先生成快照。成功 read 将解析结果作为基线，自动补 ID 等警告不另行产生 dirty；成功 save 更新基线。读取、解析、快照生成或写文件失败时保留原基线。init 创建新的文档身份。
- 节点比较包含 ID、类型、父 ID、几何、样式、Provider 提供的持久化文字和有序子树。属性键排序后比较，忽略写入先后；父子关系和子节点顺序保留。任一侧缺失 ID 时返回不相同，快照内容独立于 show/tree 的文案。
- 子图形变化向祖先传播到画布。删除后标记仍存在的父级和祖先；跨父级移动标记移动节点及两侧祖先；同父级重排标记父级和祖先，内容未变的叶子不标星。画布尺寸变化只影响画布及整体状态。
- DocumentSnapshot 保存不可变的比较内容。ShapeViews.snapshot 通过注册的 ShapeProvider.text 取正文，与 SVG 使用相同的 elementText 策略。RegisteredTreeFormatter 为 TreeNodeContext 提供按需读取的 snapshot，同次 tree 所有行共享，标签不读取时不生成；独立 subtree 未传 document 时不调用标签。
- TreeDecorator 可选的 `checkpoint(document, snapshot)` 接收保存点。回调只更新实例状态，不改文档、不执行 I/O。宿主逐个隔离异常，报告 `error: checkpoint failed: <name>` 后继续通知其他标签；诊断输出自身抛错也被隔离，已完成的 I/O 保持成功。故障标签自身的状态由插件负责。
- 装配层 CheckpointRepository 包装 DocumentRepository。write 在写入前生成快照，文件写入成功后通知；read 在解析和快照生成成功后通知。没有 checkpoint 监听者时直接调用原仓库。它不识别命令名或标签名，也不改变 EditorSession 的历史规则。createEditor 默认用 console.error 报告，CLI 传入自己的输出通道。
- modified-star 在实例 WeakMap 中按文档对象保存基线。每次 activate 创建新标签实例，模块级单例只负责注册。tree、show、stats、dir 不更新基线或历史，原有 save/read/canvas 撤销屏障保持不变。
- 多个标签按注册顺序用一个空格连接。默认先 box、后 modified-star，显示 `g#n (box) *`；反向注册显示 `g#n * (box)`。两个插件不互相导入或查询。

## 理由

内容比较让星号反映未保存结果，undo 回到保存点后能清除标记。基线以文档对象区分，可以隔离不同文档中相同的 ID。

快照通过 Provider 读取持久化文字，不必针对 text、box 等类型编写分支。检查点通知仍属于原 TreeDecorator 扩展点，只读标签无需实现这个可选方法。

将通知放在仓库包装层，可以统一处理成功读写。隔离标签回调和诊断异常，使健康标签继续收到通知，成功 save/read 的路径与历史屏障也能正常记账。按需生成快照减少无监听者和不读取快照时的额外工作。

## 影响

- 标签需要的保存点通知和渲染上下文通过通用准备提交补入框架，之后再分别完成配置接入和代码装配。分步提交证明准备完成后的接入不再修改内核和渲染器；若从首次标签开发前比较，准备阶段确实产生了修改，仍受实验 §5 首次零改动判据的限制。文件分组和 Git 证据见 [检查与修正记录](../开发检查与修正记录.md)。
- 独立测试覆盖新建、保存、编辑、undo/redo、文字、删除、移动、顺序、尺寸，以及文档和实例隔离。集成测试覆盖首次 tree 前保存、失败读写、标签顺序、自定义文字类型和只读命令。
- 回调故障的真实 CLI 回归覆盖错误诊断、保存成功反馈、无参数再次保存，以及读取后的撤销屏障。该机制未增加跨 I/O 撤销能力。
- 双装配使用相同会话和工作目录，逐字节比较 stdout 与重新保存的 SVG；禁用标签时保持 Phase 1 原始预期。
- 当前每个节点仍保存子树字符串，深链下快照的时间与内存最坏为 O(n²)，尚未改用哈希比较。
- 每个接入阶段重新采集指标并运行完整测试。[三阶段验证记录](../labels-stage-validation.json) 由 npm run test:label-stages 生成，对应临时 detached 工作树中的源码和测试组合，分别记录 328、344、345 项通过；提交边界由实际 Git 差异核对，该组合记录不承担逐阶段文档核验。
