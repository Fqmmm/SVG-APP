# ADR 004：统一激活、清单校验与暂存发布

状态：采用。

命令插件要求同时支持代码和配置装配。如果代码方式直接注册，配置方式单独校验，两条路径就容易产生不同的帮助、顺序和失败行为。

两种方式统一进入 `PluginLoader.activate`。代码方式显式选择模块，提供类型检查过的加载函数及包清单；配置方式根据模块字符串解析入口、读取清单并导入默认实例。具体插件只出现在最外层 `codePlugins.ts` 或配置文件中，加载器不维护名称映射。

清单将 shapes、commands、decorators、attributes 规范化为四个名称集合，缺省为空。激活返回后再与实际注册比较，顺序不影响集合匹配；名称必须有效且同类不重复。

每次激活使用新的 Framework 作为暂存上下文。激活结束后，先校验清单，再复核全部注册契约和宿主重名，最后同步发布。独立复核保留，用于捕获注册以后、激活返回以前被插件改写的形状契约；相应反例已纳入测试。激活抛错、清单不符或重复注册时，宿主尚未接收当前插件的贡献，丢弃暂存上下文即可回滚。已成功插件保留，后续插件继续加载。

激活上下文用于本次注册；插件不能依赖它查询宿主的内置注册，也不能在激活完成后继续动态注册。插件应把业务依赖放进注册实例。回滚范围是扩展注册，插件自行执行的文件操作或其他外部副作用不属于该事务。

配置按数组顺序加载；禁用项完全跳过模块解析与求值。相对路径以配置文件目录为准，包名使用 import-meta-resolve 的 ESM import 条件解析，包根清单使用 Node findPackageJSON 获取，入口随后由动态 import 加载。代码方式也在加载器错误边界内执行模块求值。顶层解析失败与模块求值/依赖失败分开报告，避免把缺失依赖误报成顶层插件不存在。

注册冲突和清单不匹配分别使用 RegistrationConflict、ManifestMismatch 类型，错误身份由 instanceof 判断；不根据插件抛出消息的前缀推断错误来源。

配置非法时报告一次错误并保留内置能力。插件加载错误报告后继续启动 CLI，目录命令执行期的错误由原 REPL 捕获。

验证覆盖同一实例协议的双装配、顺序与 options、禁用模块不求值、四条指定失败路径、内部及宿主重名、跨类别清单不符、异步激活失败回滚，以及 import-only/双入口包、具名与 type-only 嵌套清单、形状贡献回滚和激活后契约改写。
