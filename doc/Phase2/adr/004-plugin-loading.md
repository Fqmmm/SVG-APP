# ADR 004：统一激活、清单校验与暂存发布

状态：采用。

## 背景

插件需要同时支持代码装配和配置装配。如果代码方式直接注册、配置方式另行校验，两条路径就可能出现不同的帮助文字、加载顺序和失败行为。

插件也可能在注册部分功能后抛错，需要避免失败插件留下不完整的注册结果。

## 决策

- 两种方式统一进入 PluginLoader.activate。代码方式显式选择模块，提供经过类型检查的加载函数及包清单；配置方式按模块字符串解析入口、读取清单并导入默认实例。具体插件只出现在 codePlugins.ts 或配置文件中，加载器不维护名称映射。
- 清单中的 shapes、commands、decorators、attributes 统一整理为四个名称集合，缺省为空。激活结束后与实际注册比较，集合匹配不受声明顺序影响；名称必须有效，同类不能重复。
- 每次激活使用独立 Framework 暂存注册。激活结束后先核对清单，再复核注册对象的契约及宿主重名，全部通过后同步发布。
- 激活抛错、清单不符或重复注册时，丢弃当前暂存结果。已成功插件保留，后续插件继续加载。
- 配置按数组顺序加载，禁用项完全跳过解析与求值。相对路径以配置文件目录为基准；包名通过 import-meta-resolve 按 ESM import 条件解析，用 Node findPackageJSON 取得所属包清单，再动态 import 入口。代码方式的模块求值也在加载器错误边界内执行。
- 顶层模块解析失败与模块求值、依赖失败分别报告。注册冲突和清单不符使用 RegistrationConflict、ManifestMismatch 类型，通过 instanceof 判断，不根据插件错误文字的前缀分类。
- 配置非法时报告一次错误并保留内置能力。插件加载错误报告后继续启动 CLI；目录命令执行期间的异常仍由 REPL 处理。

## 理由

共用激活与校验过程，可以让两种装配方式遵守相同规则。暂存注册使检查发生在发布之前，失败时丢弃当前插件即可保留框架已有状态。

发布前的独立复核可以捕获插件在注册后、激活返回前改坏形状声明的问题。按错误类型分类，可以避免插件抛出相似文案时被误判为框架注册错误。

按 ESM import 条件解析入口，可以使解析结果与实际加载方式一致；区分顶层模块和内部依赖错误，也有助于定位加载失败原因。

## 影响

- 激活上下文只用于本次登记，插件不能依赖它查询宿主内置注册，也不能在激活完成后继续动态注册。业务依赖应放进注册实例。
- 回滚范围限于扩展注册。插件自行写文件或产生其他外部副作用时，需要自行处理。
- 验证覆盖双装配一致性、顺序、options 传递、禁用模块不求值、四类指定失败、内部及宿主重名、跨类别清单不符和异步激活失败回滚。
- 模块解析测试覆盖 import-only、import/require 双入口、具名与 type-only 嵌套清单；注册测试覆盖形状贡献回滚和激活返回前的契约改写。
