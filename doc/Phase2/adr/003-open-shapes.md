# ADR 003：开放图形协议与文本持久化

状态：采用。

## 背景

原来的 ShapeVisitor 为 rect、circle 等图形分别声明 visit 方法。使用它的模块需要知道完整的图形类型集合，新增类型会牵动这些接口和实现。

插件还可能提供自定义文字或复合图形，需要明确文字怎样保存、SVG 怎样读回，以及自定义读取是否可以丢弃输入内容。

## 决策

- ShapeVisitor 使用统一的 `visitShape`，由 Shape 基类分发。图形负责几何操作与状态恢复，Provider 负责参数定义、帮助、显示和 SVG 表示。
- 元素正文通过 `schema.hasText` 与 `text(shape)` 配合提供。注册时检查声明是否一致，保存时检查返回值是否为字符串。展示回调只提供摘要、位置和属性显示，序列化器不调用它。
- 容器的 CLI 文本参数存入子图形时，显式声明 `svg.text: "children"`，由 fromSvg 恢复子图形，无需父元素正文访问器。容器使用默认正文策略时直接报错。
- 解析器先检查父节点，再递归读取子图形。普通图形先执行默认读取，叶子在递归前拒绝子元素；自定义读取可通过 validateSvg 预检属性、直接文本和元数据，再由 fromSvg 构造复合图形。
- 自定义读取结果必须保留输入属性、正文，以及子图形的对象身份和顺序；返回的类型和 ID 也必须匹配。内核统一核对结果，通过后由文档登记子树，Provider 不操作私有结构句柄。
- `svg.tag` 与 `svg.kind` 定义文件表示。多个 Provider 匹配同一表示时拒绝解析；没有精确 kind 时尝试基础标签 Provider，由它决定降级或拒绝。不匹配的 kind 必须拒绝或给出降级警告。
- 普通分组的旧 box 降级规则留在 GroupProvider 中。容器是否允许解组由 canUngroup 决定。

## 理由

统一的 visitShape 让通用遍历不必枚举所有图形。图形行为和类型差异分别由图形对象与 Provider 承担。

将保存正文与终端显示分开，自定义文字图形即使没有展示实现，也能保存和读回内容。复合 Provider 按自己的参数定义保留输入语义，容器标题可以明确存入内部文字节点。

父节点先检查可以保持原有错误优先级。例如普通分组的非法正文或 kind，应先于未知子图形报错。构造后再检查属性和正文，可以发现自定义读取器遗漏数据的问题；省略可选的 validateSvg 也无法跳过这些检查。

## 影响

- 使用旧具名 Visitor 的 TypeScript 调用方需要迁移，CLI 命令与原有文件语义保持兼容。
- Provider 接收公开输入对象，不接收 XML DOM、文件系统或历史栈。
- 输入属性未保存在公开几何或样式中、正文与文本访问器结果不一致时，读入失败；子图形也不能换成另一批新建对象或改变顺序。
- 验证覆盖六类图形的具体几何与文本、自定义文字的 Unicode 和转义往返、只导入 SDK 的 tile、panel 元数据和完整子树，以及父子节点同时非法时的错误优先级。
