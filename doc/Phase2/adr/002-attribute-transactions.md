# ADR 002：属性处理保持单次编辑事务

状态：采用。

属性插件可能同时修改容器中的多个子图形。若处理器自行写入历史，或者部分修改后失败却未恢复，用户的一次 `set` 就会变成多个撤销步骤或留下半成品。

`AttributeHandler` 接收目标 `Shape`、属性名和值，通过图形公开方法修改目标或其后代。它不接收整个会话，也不直接操作历史、文档结构或画布。`handles` 必须只读；`apply` 的修改范围限于目标子树内可由 `captureState` 恢复的状态。

`SetCommand` 继续使用 `ShapeEditCommand` 的前后快照。处理器成功时只记录一个命令；undo 恢复前快照，redo 恢复后快照，不重跑插件。处理器抛错时恢复前快照，历史记录保持原状，包括已有 redo 分支。

路由先收集全部命中结果。零个命中走原属性白名单；一个命中执行该处理器；多个命中报 `ambiguous attribute handler`，不执行任何处理器。这让冲突显式暴露，不依赖加载顺序。处理器失败不回退到默认实现。

契约不允许通过外部闭包偷偷修改其他文档节点、文件或全局状态。这样的副作用超出形状快照能恢复的范围。插件作者需为自己的状态与副作用负责。

验证：一次修改两个子图形、一次 undo/redo 完整恢复；处理器修改第一个子图形后抛错，内容恢复且 redo 可继续；冲突不修改内容；无处理器时普通 `fill` 仍可修改，未知 `label` 仍报错。
