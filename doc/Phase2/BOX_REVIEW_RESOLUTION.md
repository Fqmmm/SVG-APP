# box 审查处理

本轮采纳可复现的行为与类型问题，并补齐提交证据。范围仅为 box 节点；modified-star 仍在后续节点实现。

| 意见 | 处理 |
|---|---|
| F1：fill 撤销反馈与执行相同 | 采纳。撤销输出 fill restored to，执行和重做仍为 fill propagated to；测试同时检查反馈和矩形实际填充 |
| F2：getter 再检查组件类型 | 不采纳。构造及所有结构写入路径已验证不变量，没有可复现的绕过路径；保留 getter 对已验证不变量的依赖 |
| F3：缺省 fill 以 undefined 混入属性表 | 采纳。未显式设置 fill 时不生成该键；增加 SVG 导入后的展示契约测试 |
| D1、D2：README 把历史节点写成当前状态 | 采纳。明确框架、命令插件节点当时的范围与测试数，仅修改 Phase 2 段落，Phase 1 保持原文 |
| D3、D4：缺省装配与调用位置不清 | 采纳。区分 createDefaultFramework 与默认 CLI，并注明内置 ShapeCommands 调用 ShapeViews.describeEdit |
| D5：独立测试注释归属不清 | 采纳。分别标明全部专项测试与独立插件测试 |
| E1、E3：拆分提交的指标与文件归属 | 采纳。分为通用准备、配置接入、代码装配三个可运行提交，各自采集指标并运行完整测试；test:box 随对应文件加入 |
| E2、E5：源码摘要不全且不是 Git 证据 | 移除临时摘要，以实际提交的 Git 差异检查全部既有运行代码、内核、加载器及既有插件 |
| E4：方式 B 依赖 A 的装配测试 | 采纳。先提交仅配置接入及独立 BoxConfigAssembly，再提交代码装配与 BoxAssembly 一致性测试 |

不扩展本轮范围的可选建议：展示回调继续遵循只读且不抛业务异常的契约；预检与构造的属性检查保持原实现。replaceStructure 的逐项校验保留，因为它同时检查已经从候选森林移除的容器，不能直接删掉。

修复采用先失败后通过的回归断言。最终 CLI 318 项测试、box 专项 17 项测试、类型检查、边界检查和 metrics 校验均通过。分步计数与复核命令见 [box 节点说明](BOX_PLUGIN.md)。
