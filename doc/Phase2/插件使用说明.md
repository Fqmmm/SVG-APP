# CLI 插件使用说明

CLI 默认提供六种图形和原有编辑命令，可选插件包括 stats、dir、box 和 modified-star。四类扩展点的接口、调用位置和错误契约见 [框架说明](CLI插件扩展机制.md)；设计取舍见 [ADR](adr/001-extension-boundaries.md)。

## 启动与配置

在仓库根目录运行：

```powershell
npm run build
node dist/src/main.js
node dist/src/main.js --config plugins.config.json
```

不带 `--config` 时，[codePlugins.ts](../../src/composition/codePlugins.ts) 用代码选择插件。带 `--config` 时，按指定配置加载可选插件。当前两种方式都加载 stats、dir、box 和 modified-star，顺序相同。配置模式独立读取模块列表。

在 [plugins.config.json](../../plugins.config.json) 中删除某一项或设置 `"enabled": false`，可停用相应插件。内置命令和六种基础图形仍可使用。关闭全部可选插件可运行：

```powershell
node dist/src/main.js --config doc/Phase2/plugins.none.config.json
```

插件未加载时，它提供的命令不会出现在 help 中；执行该命令得到 `error: unknown command: <name>`。

## stats

[StatsCommand](../../src/plugins/stats/StatsCommand.ts) 统计当前文档中的图形和容器。它不接收参数，执行前需要有文档。

从画布子节点按当前顺序深度优先遍历，叶子按图形类型计数，类型按首次出现的顺序输出：

```text
rect: 1  text: 1  (total 2, containers 1)
```

普通分组和 box 计入 containers，内部叶子继续计数，根 SVG 不计入。空文档输出 `(total 0, containers 0)`。统计通过 `asContainer()` 区分容器，可以统计新插件提供的图形类型。

stats 只读取文档，不改变内容、保存状态或 undo/redo 历史。

## dir

[DirCommand](../../src/plugins/dir/DirCommand.ts) 列出 CLI 进程当前工作目录的直接子项。它不接收参数，未初始化 SVG 文档时也可使用。read、save 不改变这个工作目录。

目录在前，普通文件在后，各组按 JavaScript 字符串顺序升序排列。隐藏项也会列出，`.` 和 `..` 被过滤。符号链接使用 `[LINK]`，其他特殊项使用 `[OTHER]`，这两类排在普通文件之后，不遍历链接目标。每个标记与名称之间有两个空格。

空目录输出 `(empty directory)`。读取失败输出 `error: cannot read directory: <path>`；无法取得工作目录时，路径使用 `<cwd unavailable>`。失败后 CLI 仍可继续接收命令。成功和失败都不改变文档、保存路径或 undo/redo 历史。

### 目录访问适配器

| 对象 | 职责 | 适配器模式中的角色 |
|---|---|---|
| [DirectoryAccess](../../src/plugins/dir/DirectoryAccess.ts) | 定义查询工作目录和读取子项的接口 | Target |
| `DirCommand` | 检查参数、排序和格式化结果 | Client |
| [NodeDirectoryAccess](../../src/plugins/dir/NodeDirectoryAccess.ts) | 将 Node 的目录条目转换为接口规定的数据 | Adapter |
| `node:fs.readdirSync`、`process.cwd()` | 提供真实文件系统和进程目录信息 | Adaptee |

命令测试可以替换 DirectoryAccess，分别验证混合条目、隐藏项、稳定排序、空目录和读取失败；真实适配器使用临时目录验证。未知条目类型被视为契约错误，报告 `invalid directory entry kind`。

## box

box 是包含矩形和标题的容器。[BoxProvider](../../src/plugins/box/BoxProvider.ts) 提供创建和 SVG 读回，[BoxAttributes](../../src/plugins/box/BoxAttributes.ts) 处理 fill、label，[BoxTypeDecorator](../../src/plugins/box/BoxTypeDecorator.ts) 为结构树追加 `(box)`。

下面的会话对应 Phase 1 §6.1 版本 B：

```text
init 800 600
create box n1 120 100 160 60 "开始"
create box n2 520 100 160 60 "处理数据"
create line arrow1 280 130 520 130 black
group flowchart n1 n2 arrow1
move n2 0 100
undo
set n2 fill #f5a623
set n2 label "处理数据 v2"
undo
tree
save flowchart-box.svg
```

每个 box 的矩形 ID 为 `<id>-rect`，文字 ID 为 `<id>-label`。创建前检查整个新增子树的 ID，冲突时整条命令失败。新建时矩形填充色为 `#4a90d9`，标题位置为 `(x + 20, y + h / 2 + 5)`；后续移动、缩放和对子部件的编辑按实际几何值执行。

box 支持 `in`、嵌套和额外子图形。必要的矩形与文字必须保持为直接子节点，类型分别为 Rect、Text。删除、移走或把它们包进另一个分组都会被拒绝。可以调整它们的顺序、编辑它们的属性，也可以删除整个 box。ungroup 报告 `cannot ungroup composite shape: <id>`。

| 设置操作 | 实际修改 |
|---|---|
| `set boxId fill value` | 修改内部矩形的 fill |
| `set boxId label value` | 修改内部文字的 text |

每条 set 各占一个 undo 单元。处理器部分修改后抛错时，恢复目标子树的原状态，undo/redo 历史保持不变。多个处理器同时命中时，在执行前报告冲突。没有处理器命中则沿用原属性规则，例如 stroke 修改容器自身的样式，未知属性报错。

保存使用 `<g id="..." data-kind="box">`，按实际顺序写入子节点。已加载插件时，缺少必要部件、类型错误或部件不是直接子节点会使整个 read 失败，原文档、路径和历史保持不变。重复 ID 始终导致读入失败。未加载插件时，按普通 g 读入并警告降级；再次保存会丢失 box 标记。

结构约束与导入策略见 [ADR 005](adr/005-composite-containers.md)，属性事务见 [ADR 002](adr/002-attribute-transactions.md)。

## modified-star

[ModifiedStarDecorator](../../src/plugins/modified-star/ModifiedStarDecorator.ts) 在结构树行尾用 `*` 标记未保存的变化。它比较当前模型与最近一次成功 read/save 的内容，修改后 undo 回到保存内容时，星号消失，redo 后再次出现。`move 0 0` 这类未改变内容的操作不产生新的差异。

新建文档尚无保存基线，画布及新节点立即标星；第一次成功 read/save 建立基线。比较内容包括几何、样式、Provider 提供的持久化文本、父级关系和子节点顺序。子节点变化向祖先传播，画布尺寸变化只影响画布行。删除节点后标记仍存在的父节点及祖先，跨父级移动同时影响原父级与新父级。调整同级顺序会标记父级和祖先，未变化的叶子不标星。

星号与 `(box)` 标签互不感知，按注册顺序拼接。默认显示 `g#n (box) *`，交换注册顺序则显示 `g#n * (box)`。停用 modified-star 后仍可保留 `(box)`。标签只影响终端显示，不写入 SVG。

标签实例用 WeakMap 保存各文档的基线。tree、show、stats、dir 不改变基线或历史，init 创建新的文档身份。失败的读写保留原基线。检查点回调抛错时，宿主输出 `error: checkpoint failed: <name>`，继续通知其余标签，成功 I/O 的路径和历史屏障照常记账。

树快照按需生成，同一次 tree 共享一份快照；没有实现 checkpoint 的标签时，读写跳过额外投影。dirty 的具体选择见 [ADR 006](adr/006-content-checkpoints.md)。标签接入的历史提交与验收限制见 [检查与修正记录](开发检查与修正记录.md)。

## 插件加载契约

[PluginLoader](../../src/composition/plugins/PluginLoader.ts) 位于宿主装配层。代码方式通过 `loadCode` 提供加载函数，配置方式根据模块名动态导入默认实例；两者都经过 activate、清单校验和暂存注册发布。

相对路径以配置文件目录为基准；包名按 ESM import 规则解析。模块的 package.json 声明 `contributes`，四类名称列表与实际注册结果逐项核对。options 原样传给 `activate(context, options)`。stats、dir 当前没有可配置参数。配置按数组顺序加载，`enabled: false` 在解析和求值前跳过。

注册先进入独立的暂存上下文。名称集合、注册对象和重复名称检查全部通过后，才发布到框架。失败时丢弃当前插件的暂存注册，保留已成功插件并继续后续加载。

| 失败情况 | 输出 |
|---|---|
| 模块找不到 | `error: plugin not found: <module>` |
| 没有默认导出 | `error: plugin has no default export: <module>` |
| 清单与实际注册不一致 | `error: plugin manifest mismatch: <name> (declared: …, registered: …)` |
| 模块求值、依赖或激活失败 | `error: plugin failed to activate: <name> (<reason>)` |
| 同类注册名重复 | `error: duplicate registration: <category>/<name>` |
| 配置无法读取或结构非法 | `error: invalid plugin config`，保留内置能力继续启动 |

加载器通过固定版本的 import-meta-resolve 解析 ESM 包入口，再用 Node 的 findPackageJSON 读取模块所属清单。相对插件从自己的目录读取 package.json.main，不向上寻找带 contributes 的其他清单。当前插件与框架一起构建，入口指向仓库 dist；独立发布时还需安排 SDK 和包入口。代码装配按项目 package.json 定位仓库。细节见 [ADR 004](adr/004-plugin-loading.md)。
