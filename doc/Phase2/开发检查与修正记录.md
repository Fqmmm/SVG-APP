# AI 协作检查与修正

开发中对 AI 建议的核查集中在可复现行为、接口契约和 Git 提交范围。以下记录汇总框架、box 和标签阶段的修正，保留影响结果的取舍。功能用法见 [插件说明](插件使用说明.md)。

## Phase 1 重构

Phase 1 将 CLI 分发拆为文档、图形、结构和查询处理器，由 EditFeedback 统一编辑反馈与撤销重做文案。CLI 和 SVG 读取各自转换参数，通过 ShapeInput、ShapeSchema、ShapeDefinition 共享创建逻辑，避免把 SVG 属性重新拼成命令行再解析。

SVG 解析拆为 XML 根节点检查、画布创建、ID 分配和子图形读取，保留错误优先级、缺省值和读入失败不替换原文档的行为。分组操作将目标选择、共同父级和插入位置计算分开，由 StructureEdit 记录受影响列表的前后状态，保证一次 group 对应一个撤销单元。

这次重构增加四项回归断言，覆盖共享 undo 历史、文档错误优先级和 CLI/SVG 参数差异。2026-11-09 的记录为原有 224 项加新增 4 项，共 228 项通过；类型和格式检查也通过。对应测试是 [RefactoringCompatibility](../../tests/cli/RefactoringCompatibility.test.ts) 和 [SvgShapeReader](../../tests/infrastructure/SvgShapeReader.test.ts)。

## 框架与导入契约

| 检查发现 | 处理结果 | 验证依据 |
|---|---|---|
| 持久化文本混入展示回调，文本读写规则不一致 | 使用独立的 `text(shape)` 访问器，注册时检查它与 hasText 的对应关系 | [ReviewRegression](../../tests/extensions/ReviewRegression.test.ts) 检查 Unicode、转义、缺失访问器、非法返回值和旧 content 字段 |
| 父节点错误可能被未知子图形错误掩盖 | 父节点默认读取或 validateSvg 在递归前执行；内置叶子先拒绝子元素 | [ImportContracts](../../tests/extensions/ImportContracts.test.ts) 验证错误优先级 |
| 自定义导入器可能丢弃属性、正文或 kind | 内核核对输入保留情况，预检回调可选 | 同上，覆盖属性丢失、正文丢失、空预检、合法读回及失败读取保留 redo |
| 容器声明文本参数却没有明确存储位置 | 容器将 CLI 文本存入子图形时显式声明 `svg.text: "children"`；默认元素正文策略拒绝容器 | 同上，覆盖创建和序列化两条路径，叶子不能使用子图形文本策略 |
| 插件能访问装配代码和私有内核模块 | 插件统一从公开 SDK 导入，增加依赖反例检查 | [Metrics](../../tests/extensions/Metrics.test.ts) 验证非法依赖 |
| 扩展点只有测试替身，缺少类实现 | 增加 Provider 类、BoundCommand、HelpCommand，以及默认关闭的标签和属性示例 | [ExamplePlugins](../../tests/extensions/ExamplePlugins.test.ts) 验证注册、调用与原属性缺省行为 |
| 同一图形的信息分散在多个映射 | Provider 集中创建定义、SVG 映射、展示和文本访问 | 默认 help、基础图形与 SVG 回归测试 |
| 未注册图形暴露内部查找异常 | 展示和序列化统一报告 `unknown shape type: ... (is the plugin loaded?)` | 未注册文档图形的错误测试 |
| 指标只按文件角色汇总，缺少行数、模块和过期检查 | 增加分类行数、具名模块图、源文件集合及摘要校验 | [采集脚本](../../scripts/collect-metrics.mjs) 和 Metrics 测试 |

删除了重复的 Attribute/PositionFormatter，文件仓库共用工厂；当时保留默认构造入口供调用方使用。后续目录重构又移除了旧路径转发文件，将默认构造集中到 `composition/defaults`，内核依赖检查不再需要旧路径例外。

## box 的修正与保留选择

| 检查发现或建议 | 处理结果 |
|---|---|
| fill 执行与撤销的反馈文案相同 | 执行显示 fill propagated to，撤销显示 fill restored to；测试同时核对文案和实际值 |
| 缺省 fill 在展示中出现 undefined | 未显式设置时省略该键，与 SVG 输出一致 |
| 建议 getter 再检查必要部件 | 构造及结构写入已统一验证，保留在这些入口检查的做法 |
| 只在个别命令保护子部件，可能漏掉其他结构修改 | Group 提供通用子节点约束，文档结构写入统一校验；保留对被移出候选森林的容器的检查 |
| 展示回调可能承担业务修改 | 保留只读、不抛业务异常的契约，预检和构造后的校验继续使用分开的接口 |
| 文档混用历史状态和当前状态 | 区分框架、box 和标签阶段，分别注明测试范围与提交边界 |
| 临时源码摘要不足以证明零改动接入 | 以实际提交的 Git 差异核对内核、加载器和既有插件 |

属性处理器的事务作用域是目标子树中的可恢复状态。它通过公开图形方法修改属性；任意修改整份文档结构不在该事务的支持范围内。结构不变量由文档结构约束维护。取舍见 [ADR 002](adr/002-attribute-transactions.md) 和 [ADR 005](adr/005-composite-containers.md)。

box 专项中的独立测试、真实读写与双装配分别见 [BoxPlugin](../../tests/plugins/BoxPlugin.test.ts)、[BoxIntegration](../../tests/plugins/BoxIntegration.test.ts)、[BoxAssembly](../../tests/composition/BoxAssembly.test.ts) 和 [BoxConfigAssembly](../../tests/composition/BoxConfigAssembly.test.ts)。

## 标签与保存点通知

CheckpointRepository 隔离每个 checkpoint 回调的异常，报告失败标签后继续通知其他标签。诊断输出自身抛错也不会中断成功 I/O 的路径和历史屏障记账。回归覆盖首次 tree 前保存、失败读写、无参数再次保存、重新读取、故障标签和不同注册顺序。

删除与跨父级移动测试各自建立干净基线，分别检查节点缺失和父级变化的影响。比较属性时忽略键的写入顺序，保留子节点顺序；缺失 ID 直接返回不相同。新文档没有基线时直接标星。

快照按需创建，同次 tree 共享。未注册 checkpoint 监听者时，读写跳过投影。当前逐节点比较包含完整子树的规范表示，退化深链下最坏仍可能有 O(n2) 的时间和内存开销；本次保留这项实现取舍。

验证见 [ModifiedStar](../../tests/plugins/ModifiedStar.test.ts)、[ModifiedStarIntegration](../../tests/plugins/ModifiedStarIntegration.test.ts) 和 [CheckpointRepository](../../tests/composition/CheckpointRepository.test.ts)。快照与通知契约见 [ADR 006](adr/006-content-checkpoints.md)。

## 提交与验收边界

| 功能 | 准备提交 | 配置接入 | 代码装配 |
|---|---|---|---|
| box | `1af7bae`：容器约束、展示钩子、公开模型 | `9559e0c`：插件和配置 | `8f3aeb0`：codePlugins.ts 选择插件 |

配置接入阶段使用 box-only fixture 保留旧 box 会话，标签会话使用根配置；代码装配完成后，box 会话恢复根配置并更新星号预期。Phase 1 会话通过 tests/fixtures 中的空配置保留原始输出。

复核两个配置接入提交可运行：

```powershell
git diff 9559e0c^ 9559e0c -- src ':(exclude)src/plugins/box'
git diff f47e813^ f47e813 -- src ':(exclude)src/plugins/modified-star'
```

这两次插件接入提交的上述源码差异为空。代码装配提交在 src 中只修改 codePlugins.ts。检查应使用固定提交并覆盖内核、加载器及全部既有插件。

标签需求推动了 TreeDecorator 上下文、保存点通知和渲染器的准备改动。分步提交证明准备完成后的接入边界；从首次标签开发前开始比较，内核与渲染器发生过改动。因此，若严格按实验 §5 的首次零改动判据验收，这项限制仍然存在。

[阶段验证脚本](../../scripts/verify-label-stages.mjs) 在临时 detached 工作树中组合源码与测试，分阶段重采指标并运行检查，记录见 [labels-stage-validation.json](labels-stage-validation.json)。该记录证明对应组合的运行结果；实际提交范围由 Git 历史核对。清理使用嵌套 finally，工作树移除失败后仍尝试清理临时目录并注销登记。阶段记录中的文件数量和摘要对应当次生成，不作为当前源码清单。
